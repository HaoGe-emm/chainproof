# ChainProof — 2–3 分钟演示

这条演示路径只读取已有主网数据，不需要新增登记交易。当前真实示例原文件暂缺，所以现场演示 MISMATCH，不声称演示了真实文件 MATCH。

## 准备

- 本地：`npm run dev`，打开 `http://localhost:3000`。网站部署后用实际域名替换本地地址；localhost 的二维码不能直接分享给另一台设备。
- 钱包如可用，选择真实示例登记者 `0x89f415bb42e356e8b892c10b05522e0a8ef151f3`，BOT Chain Mainnet（677）。如果没有这个账户，My Proofs 展示当前钱包实际历史，可能为空，不伪装示例归属。
- 准备 `docs/demo-mismatch.txt` 作为有意不匹配的文件；该文件是演示素材，不声称已上链。
- 预先打开真实证书和 BOTScan，并检查 RPC。保留已加载证书的打印 PDF 作为离线展示副本，明确其不是实时验证。

## 备用路径

- MetaMask 不可用：展示 Create Proof 本地哈希计算；My Proofs 展示连接提示并解释此功能需要钱包。直接进入真实公开证书和 BOTScan，完成无钱包只读路径，不冒充历史查询成功。
- RPC 不可用：展示 Verification Error 与 Retry；打开预先加载的 BOTScan 或事先保存的 PDF，明确标注“此前读取的展示副本，当前无法实时核实”。不要显示 MATCH 或假造 Registered。网络恢复后重新查询。
- 没有已登记钱包：My Proofs 展示实际空历史，随后从首页真实示例进入证书，不将别的钱包记录说成当前用户的。
- 真实原文件找不到：仅演示 MISMATCH；MATCH 使用隔离测试夹具完成自动化验证，不把测试夹具当作主网登记记录。

## 本地人工验收

1. 在 320、375、768、1440px 检查四页导航及选中状态。
2. Create Proof 选择文件、清除文件、检查可重试错误与重复登记原因。不要实际点击钱包的交易确认。
3. Verify Provenance 选择文件，检查 Registered Fingerprint Found / No Matching Proof / Verification Error；错误时 Retry。
4. My Proofs 换账户、断开钱包、切换网络，确认旧记录即时清除；观察 Scanning / Partial Results / Scan Complete / Scan Failed。
5. 从真实示例打开公开证书，选择 demo-mismatch.txt；确认 Registered 保持为链上状态，文件结果独立显示 MISMATCH。
6. 复制链接、扫描实际部署域名的二维码；打印 A4，浏览器自带页眉页脚可在打印面板里关闭。
7. 若已提交过一笔实际交易，刷新会用本标签页保存的公开交易信息恢复回执查询，不重新提交；若浏览器禁用会话存储，页面会提示保留交易链接，刷新不能恢复进度。本阶段开发测试不需要新增任何主网交易。
